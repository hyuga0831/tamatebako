# 玉手箱ドリル

Web テスト「玉手箱」の足切りラインを、最短で超えるための練習アプリ。スマホで使うことを前提にしていて、PC でも使える。

満点を目指すアプリではない。「ボーダー予想 ＋ 10 ポイント」を取れる見込みになったらゲージが 100% になり、そこでやめてよい。

## できること

- 5 つの出題形式を練習できる
  - 計数：四則逆算、図表の読み取り、表の空欄推測（問題は毎回自動で作るので、同じ問題は出ない）
  - 言語：論理的読解（GAB形式）、趣旨判定（IMAGES形式）（各 16 長文・64 設問）
- 3 つのモード：ドリル（1問ごとに解説）、ミニ模試（本番と同じペースで時間を計る）、本番模試（本番と同じ問題数）
- 足切り突破ゲージ：直近の正答率と解く速さから本番の得点を予測し、目標への到達度を表示する
- 「次にやること」：ゲージがいちばん伸びる形式とモードを 1 つだけ勧める
- 受検案内の制限時間を入れると、出る形式だけに絞り込む
- 画面内の電卓（スマホで計数を解くため）
- 記録は端末のブラウザ（localStorage）に保存。サーバーはない。一度開けば電波がなくても使える（PWA）

英語と、言語の「趣旨把握」は入っていない。

## 動かす

```
npm install
npm run dev      # 開発用サーバー（同じ Wi-Fi のスマホからも開ける）
npm test         # 問題の生成・ゲージの計算・電卓のテスト
npm run build    # dist/ に本番用のファイルを作る
```

## 中身

| 場所 | 内容 |
|---|---|
| `src/gen/` | 計数の問題を作る。四則逆算は 7 系統、図表は 12 場面、空欄推測は 8 規則 |
| `src/data/` | 言語の長文と設問、解説（すべて書き下ろし） |
| `src/lib/stats.ts` | ゲージの計算 |
| `src/lib/formats.ts` | 形式ごとの本番の問題数・制限時間、攻略メモ |
| `src/lib/session.ts` | 1 セットで出す問題の組み立て |
| `src/lib/store.ts` | 記録の保存と読み込み |
| `src/screens/` | 画面（ホーム、形式のページ、出題、結果、設定） |

### ゲージの計算

形式ごとに、直近の解答（四則逆算なら 40 問）から次を出す。

1. 正答率と、1問あたりの秒数
2. その速さで本番の制限時間内に手が届く問題数
3. 予想得点率 ＝（届く問題数 × 正答率 ＋ 届かない問題数 × 勘で当たる確率）÷ 全問題数
4. 形式のゲージ ＝ min(1, 予想得点率 ÷ 目標) × データの十分さ（解いた数 ÷ 必要数）

全体のゲージは、出る可能性がある形式について、計数の平均と言語の平均を半分ずつ足したもの。

### 問題について

玉手箱に公式の過去問はない。このアプリの問題は、公開されている例題の出題パターン（式の形、図表と設問の種類、設問の作られ方）を調べたうえで、数値・文章ともすべて新しく作っている。

言語の長文は約 280 字で、本番（400〜600 字）より短い。その分、アプリ内の制限時間を本番の約 7 割に縮めている（`formats.ts` の `timeScale`）。

## 公開

- 公開先：GitHub Pages（https://hyuga0831.github.io/tamatebako/ 。独自ドメイン `tamatebako.tougaxx.com` を付ける予定）
- `main` に push すると、`.github/workflows/deploy.yml` がテスト → ビルド → 公開まで行う。テストが落ちたら公開されない。
- 学習の記録は URL（オリジン）ごとに別になる。公開先の URL を変えるときは、先に設定画面の「書き出す」で記録を控える。

## 動作確認

```
npm run build
npx vite preview --port 4173 --strictPort    # 別のターミナルで
node scripts/shots.mjs <出力フォルダ>          # 主な画面を操作して撮影。はみ出しとエラーを検査
node scripts/timeup.mjs                       # ミニ模試の時間切れを実測（約 2 分）
```

出題画面の URL に `?seed=数字` を付けると、同じ問題を再現できる（例：`#/q/zuhyo/drill?seed=5`）。
